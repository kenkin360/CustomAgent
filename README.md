# CustomAgent

Flow host contains exactly four files: `App.tsx`, `Bundle.js`, `Resource.js`, and `Function.extend.js`. Copy those four files into Flow host using the same filenames. `App.tsx` is a small `Function.extend(React.Component)` loader, following FlowerX's entry point. `Bundle.js` loads the following plain JavaScript files from this repository through `esm.sh` as classic scripts, in dependency order:

- `UpscaleCode.js` — installable Function.extend WebSR extension
- `views/agent.html.js` — interface markup and styles
- `DrawingCode.js` — installable Function.extend rectangle extension
- `ImageService.js` — Flow media, camera, generation, and download operations
- `Assistant.js` — text model calls, welcome, conversation, action decisions, and replies
- `CustomAgent.js` — the App, its UI API, state, runtime installation, source inspection, and rollback

Every remotely loaded file is a classic script with a top-level `var` whose name exactly matches its `Bundle.Config` key. `Resource.Module` reads that name from `globalThis`; classic scripts expose top-level `var` there without an explicit assignment. Remote scripts have no top-level `import` or `export`. Both extension files contain `export default` only inside the JavaScript source strings passed to `installCode` at startup. The host's `Bundle.js` and `Resource.js` remain ES modules because `App.tsx` imports them.

`Bundle.js` pins the remote source commit so Flow loads these exact scripts without an earlier `esm.sh` cache of the default branch.

`Assistant` subscribes to App messages and events, reads the App state, calls `Flow.generate.text`, and sends its answers through `CustomAgent.Reply`. The welcome message and operation results are generated by the model. The model receives up to 20 preceding messages plus the current message separately. Image generation starts only after the user chooses Generate. The UI supports multiple input lines with Shift+Enter.
