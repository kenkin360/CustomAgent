# CustomAgent

Flow host contains exactly four files: `App.tsx`, `Bundle.js`, `Resource.js`, and `Function.extend.js`. Copy those four files into Flow host using the same filenames. `App.tsx` is a small `Function.extend(React.Component)` loader, following FlowerX's entry point. `Bundle.js` loads the following plain JavaScript files from this repository through `esm.sh` as classic scripts, in dependency order:

- `views/agent.html.js` — interface markup and styles
- `Extensible.js` — marker base class for installable extensions
- `ImageService.js` — Flow media, camera, generation, and download operations
- `Assistant.js` — text model calls, welcome, conversation, action decisions, and replies
- `CustomAgent.js` — the App, its UI API, state, extension registration, source inspection, and rollback

Every remotely loaded file is a classic script with a top-level `var` whose name exactly matches the requested resource name. `Resource.Module` reads that name from `globalThis`; classic scripts expose top-level `var` there without an explicit assignment. Remote scripts have no top-level `import` or `export`. The host's `Bundle.js` and `Resource.js` remain ES modules because `App.tsx` imports them. `App.tsx` also exposes `App`, `Bundle`, and `Resource` to the loaded scripts.

`DrawRectangle.js` and `UpscaleCode.js` each define one `Function.extend(Extensible, ...)` class. They are loaded through `Resource.Module` after the App starts and register their runtime actions in their constructors. The App retains the extension instances for the current session. An assistant-authored extension follows the same class format and is loaded with the `loadModule` action using a script URL or JavaScript source. Each update should use a fresh class name; rollback restores the previous runtime registrations and UI state. `UpscaleCode` loads WebSR from `https://esm.sh/gh/sb2702/websr/dist/websr.js?raw` when first used.

`Assistant` subscribes to App messages and events, reads the App state, calls `Flow.generate.text`, and sends its answers through `CustomAgent.Reply`. The welcome message and operation results are generated by the model. The model receives up to 20 preceding messages plus the current message separately. Image generation starts only after the user chooses Generate. The UI supports multiple input lines with Shift+Enter.
